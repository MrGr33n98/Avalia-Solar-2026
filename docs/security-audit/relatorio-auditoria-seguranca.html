Pontos fortes

✓ Mecanismo de isolamento identificado: filtros manuais por empresa/associação, memberships ativas e Pundit; vários controllers usam escopos aninhados.

✓ Usuários: show/update/destroy têm autenticação e bloqueio para o próprio usuário ou admin (users_controller.rb:3-5, 119-131).

✓ Lead distributions: autenticação e autorização por company/membership (lead_distributions_controller.rb:2-4, 42-49).

✓ Intent scores: autenticação, empresa derivada do score e Pundit/feature gate antes da resposta (intent_scores_controller.rb:6-9, 80-90).

Pontos fracos centrais

Segredo criptográfico versionado, defaults de banco permissivos, status de proposta sem posse e JSON-LD raw em contexto HTML.

críticaAB0-1-back/config/credentials.yml:9Chaves expostas
secret_key_base está versionado em texto claro. O valor protege MessageVerifiers e cookies Rails; qualquer leitor do repositório pode forjar tokens/cookies assinados.
secret_key_base: [REDACTED]
Impacto: Comprometimento de sessões e dados protegidos.
Correção: Revogar/rotacionar imediatamente; remover do histórico; usar Rails credentials cifradas ou secret manager; bloquear startup sem segredo de produção.
altaAB0-1-back/config/database.yml:28-30Chaves expostas
Configuração de produção aceita host, usuário e senha padrão quando variáveis estão ausentes, incluindo password.
password: <%= ENV.fetch("POSTGRES_PASSWORD") { "password" } %>
Impacto: Deploy mal configurado pode conectar com credencial previsível.
Correção: Usar ENV.fetch sem fallback em produção e falhar no boot; validar POSTGRES_PASSWORD e demais segredos.
altaAB0-1-back/app/controllers/api/v1/financing_proposals_controller.rb:91-95IDOR
status busca Lead apenas por params[:id], sem autenticação, posse ou conferência com company_id.
lead = ::Lead.find(params[:id])
Impacto: Qualquer cliente que conheça um ID pode consultar status de proposta de outro cliente.
Correção: Exigir autenticação apropriada e buscar por company/owner; usar escopo autorizado e identificador não enumerável.
médiaAB0-1-front/app/companies/[id]/categories/[categorySlug]/page.tsx:114-117; AB0-1-front/app/companies/CompaniesPageClient.tsx:654-659; AB0-1-front/app/melhores-empresas/[category_slug]/[state]/[city]/page.tsx:150-153XSS
JSON.stringify de dados que podem conter conteúdo persistido é inserido diretamente em script via dangerouslySetInnerHTML. JSON não escapa para contexto HTML.
dangerouslySetInnerHTML={{ __html: JSON.stringify(itemList) }}
Impacto: Conteúdo armazenado com fechamento de script pode injetar markup/script na página.
Correção: Serializar para contexto HTML seguro, escapando <, >, &, ou usar utilitário de JSON-LD seguro; validar campos e CSP como defesa secundária.

Recomendações priorizadas

  1. P1: rotacionar secret_key_base e revisar histórico Git; bloquear boot de produção sem segredos.
  2. P1: proteger status de propostas por autenticação e escopo de proprietário/empresa.
  3. P2: substituir defaults de database.yml por validação obrigatória no ambiente de produção.
  4. P2: trocar inserções JSON-LD por serialização HTML-safe.
  5. P3: adicionar testes de autorização/IDOR para todos os recursos sensíveis e rodar Gitleaks no histórico.
