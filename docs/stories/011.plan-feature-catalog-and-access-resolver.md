# Story 011: Plan Feature Catalog and Access Resolver

## Contexto

O sistema já possui `Plan.features_json` e helpers de feature gating, mas ainda sem catálogo canônico nem resolvedor único.

## User Story

Como plataforma,
quero resolver acesso por feature a partir de um catálogo central,
para que plano, dashboard, perfil público e APIs compartilhem a mesma lógica.

## Escopo

- definir catálogo canônico de feature keys
- criar resolvedor central de acesso por empresa
- mapear aliases legados
- padronizar estados `enabled`, `locked`, `hidden`

## Critérios de aceite

- existe um catálogo único de features monetizáveis
- o resolvedor considera `plan`, `plan_status` e overrides
- o payload final de acesso é serializável para frontend
- flags legadas críticas possuem camada de compatibilidade temporária
- `active_admin` deixa de ser tratado como plano pago em novas regras

## Dependências

- nenhuma

## Riscos

- manter dupla semântica entre plano e flags antigas

## Verificação

- specs do resolvedor por plano
- specs de compatibilidade de alias
