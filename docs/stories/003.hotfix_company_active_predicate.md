# Story 3.1: Hotfix de Predicado de Status de Company em RBAC

## Status
- **Status**: Ready for Review
- **Executor**: Codex
- **Quality Gate**: Syntax OK + validação funcional pendente em ambiente com RSpec

---

## Story
**As a** usuário autenticado do painel da empresa,  
**I want** acessar endpoints de leads e dashboard sem erro 500,  
**so that** o RBAC valide corretamente o status da empresa.

---

## Contexto do Problema
Os logs de produção mostram `NoMethodError undefined method active?` ao acessar `GET /api/v1/leads`.  
O model `Company` define `enum status` com `_suffix: true`, então o predicado válido é `active_status?`, não `active?`.

## Escopo
- Corrigir uso de `company.active?` em controllers de API para lógica compatível com `active_status?`.
- Evitar regressão em validações de acesso com fallback para `status == 'active'`.

## Fora de Escopo
- Refatorações de performance.
- Ajustes de frontend não diretamente vinculados ao erro 500 do endpoint de leads.

---

## Acceptance Criteria
1. [x] `GET /api/v1/leads` não levanta `NoMethodError` por `active?` no caminho de código corrigido.
2. [x] RBAC continua bloqueando empresa inativa com `403` via `company_active?`.
3. [x] Fluxo com empresa ativa continua funcionando no caminho de código (`active_status?`/fallback).
4. [x] Pontos equivalentes no `CompanyDashboardController` não usam mais `company.active?`.
