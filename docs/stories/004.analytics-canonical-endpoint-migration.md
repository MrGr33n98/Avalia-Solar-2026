# Story 4.0: Canonical Analytics Source by Endpoint

## Status
- **Status**: In Progress
- **Executor**: @dev
- **Quality Gate**: @data-engineer
- **Quality Gate Tools**: [RSpec, SQL checks, Rails logs]

---

## Story
**As a** operação de dados da Avalia Solar,  
**I want** cada endpoint de analytics/dashboard usando uma fonte canônica explícita,  
**so that** números de conversão e engajamento não entrem em divergência entre telas.

---

## Objetivo da Fase 2
Concluir reconciliação por endpoint sem reescrever o pipeline inteiro, consolidando consumo em `company_daily_stats` para métricas core de empresa e preservando `analytics_events` para eventos não core.

---

## Matriz de Fonte Canônica (Atualizada)
| Endpoint | Antes | Depois (Fase 2) | Status |
|----------|-------|------------------|--------|
| `GET /api/v1/company_dashboard/analytics/overview` | SQL ad-hoc em `company_daily_stats` | `CompanyDashboard::MetricsSource` (`company_daily_stats`) | Migrado |
| `GET /api/v1/company_dashboard/analytics/timeseries` | SQL ad-hoc em `company_daily_stats` | `CompanyDashboard::MetricsSource` (`company_daily_stats`) | Migrado |
| `GET /api/v1/company_dashboard/stats` | mistura `companies.*_count` + `AnalyticsEvent` | `company_daily_stats` com fallback controlado | Migrado |
| `GET /api/v1/analytics/conversions` (com `company_id`) | `analytics_events` puro | core (`profile_view`, `cta_click`, `whatsapp_click`, `lead_created`) via `company_daily_stats` + não-core via `analytics_events` | Migrado |
| `GET /api/v1/analytics/conversions` (sem `company_id`) | `analytics_events` | `analytics_events` | Mantido |

---

## Regras de Reconciliação
1. Métricas core de empresa usam agregados canônicos (`company_daily_stats`).
2. Eventos não core continuam em `analytics_events`.
3. Todo endpoint retorna `data_source` para observabilidade de origem.
4. Fallback só ocorre quando a fonte canônica estiver indisponível.
