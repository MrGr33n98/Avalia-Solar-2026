# Arquitetura alvo incremental
Frontend atual `AB0-1-front`; backend Rails e APIs existentes permanecem. `app/dashboard/components/EnterpriseDashboard` continua entry empresarial. Não criar novo app Next paralelo em produção. Introduzir `components/dashboard-system/{tokens,primitives,patterns,layouts,charts,tables,forms}` (caminhos propostos) com adapters aos componentes atuais. Regra de dependência: tokens → primitives → patterns → domain screens → shell. Domain hooks isolam leitura/mutação. `config/navigation.ts` permanece fonte única. System admin, CRM e reviewer mantêm políticas próprias; compartilham primitives, não data providers.

- `DashboardShell`, `Sidebar`, `Toolbar`, `PageHeader`, `SectionHeader`, `FilterBar`, `MetricCard`, `ChartFrame`, `DataTable`, `TableToolbar`, `Pagination`, `EntityDrawer`, `ConfirmDialog`, `FormSection`, `StatusBadge`, `EmptyState`, `ErrorState`, `LockedState`, `Skeleton`, `Toast`, `OfflineBanner`, `SourceNote`, `ActivityFeed`.
- Dados: domain adapter + query keys [domain, tenant, filters, page]; tenant verificado antes de enabled. AbortSignal/cancel; stale responses ignoradas; invalidation após mutation por escopo; nenhum fallback global de PII. Subscriptions cleanup. URL normalizada por schema, IDs estáveis, filtros debounced só quando necessário. Export server-side quando volumoso e sempre escopado. Usar APIs reais, sem inventar endpoint.
- Layout: shell estável e skeleton de seção; lazy por tab; charts e drawers code split; SSR/CSR conforme API/autorização existentes; evitar import barrel que carrega domínio todo. Sem cache público de dados autenticados. Feature flags por domínio, default off; configuração/flag atual deve ser confirmada. Rollback não reverte dados persistidos.
- UI registry Spec 021: compartilhar somente tokens/contratos puros quando homologados. Não carregar `packages/mcp-ui` no dashboard nem aumentar bundle MCP. Backend changes só quando falha de contrato comprovada e testes específicos.
- Protótipos em worktree local com stack existente; dependências/lockfile inalterados para o redesign visual, audit/SBOM revisados. Sem nova VM/processo.
