## Audit Summary

### Backend (Rails 7, Ruby 3.2, PostgreSQL, Sidekiq, Redis)
- **API pattern:** `Api::V1::BaseController` with JWT auth, Pundit, Paginatable, edge geolocation, UTM capture
- **Services:** Namespaced (e.g., `Analytics::`, `SaasLeads::`, `Billing::`) — follow same pattern for `Chat::`
- **Serializers:** ActiveModelSerializers (`active_model_serializers ~> 0.10.15`)
- **Active Admin:** 46 admin files, robust patterns with filters, scopes, actions, CSV exports
- **PostHog:** `posthog-rails` gem installed, backend webhook at `posthog_webhooks_controller.rb`
- **Sidekiq:** Installed with `sidekiq-scheduler` for cron jobs
- **Rate limiting:** `rack-attack` gem present
- **Consent:** `consent_logs` table and `consent_controller.rb` exist — reuse pattern
- **Lead model:** Rich with UTM, OTP, wizard_status, score, SlackNotification, Analytics tracking
- **Slack:** `SlackNotificationService` with channel routing — add `:chat_leads` channel
- **ActionCable:** Mounted at `/cable` — available for streaming if needed later
- **HTTP Client:** `httparty` gem available for LLM API calls

### Frontend (Next.js, TypeScript, Tailwind-free vanilla CSS + shadcn/ui)
- **Layout:** `layout.tsx` with ThemeProvider, UtmProvider, ClientBody, PostHog preconnects
- **PostHog:** Full integration in `lib/posthog.ts` with `posthogEvents` object, feature flags
- **Analytics:** `lib/analytics/` with consolidated tracking layer (PostHog + GTM + backend)
- **UI Components:** shadcn/ui (`components/ui/`), BannerSlot pattern, custom Cards, Buttons
- **API Layer:** `lib/api.ts` with typed interfaces, `lib/api-client.ts` for safe fetching
- **Hooks:** Custom hooks pattern (`hooks/useBannersQuery.ts`, etc.)

### Key Decisions
- **LLM Provider:** OpenAI API via `httparty` (no new gem needed for MVP)
- **No pgvector:** RAG stub only — simple DB queries for context
- **No WebSocket streaming:** MVP uses standard POST/response (ActionCable ready for v2)
- **Metabase:** No API — just SQL-friendly schema with proper indexes

## Metabase SQL Queries (Ready-to-use)

```sql
-- Leads por dia
SELECT DATE(created_at) as dia, COUNT(*) as total FROM chat_leads GROUP BY 1 ORDER BY 1 DESC;

-- Leads por cidade
SELECT city, state, COUNT(*) as total FROM chat_leads WHERE city IS NOT NULL GROUP BY 1,2 ORDER BY 3 DESC;

-- Leads por vertical
SELECT vertical, COUNT(*) as total FROM chat_leads GROUP BY 1 ORDER BY 2 DESC;

-- Leads por temperatura
SELECT lead_temperature, COUNT(*) as total FROM chat_leads GROUP BY 1 ORDER BY 2 DESC;

-- Leads por origem
SELECT source_page, COUNT(*) as total FROM chat_leads GROUP BY 1 ORDER BY 2 DESC;

-- Taxa de conversão do chat
SELECT
  (SELECT COUNT(*) FROM chat_sessions) as sessoes,
  (SELECT COUNT(*) FROM chat_leads) as leads,
  ROUND(
    (SELECT COUNT(*) FROM chat_leads)::numeric /
    NULLIF((SELECT COUNT(*) FROM chat_sessions), 0) * 100, 2
  ) as taxa_conversao;
```
