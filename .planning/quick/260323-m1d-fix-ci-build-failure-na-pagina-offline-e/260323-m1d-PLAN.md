# Fix CI Build Failure - `/offline` page SSG

## Diagnóstico

O CI falhou com:
```
Export encountered errors on following paths:
/offline/page: /offline
```

Stack trace aponta para o runtime compilado do Next.js (`app-page.runtime.prod.js`), não para código de aplicação.

**Importante:** Build local passou com sucesso (exit 0). O erro é específico do ambiente Docker/CI.

## Hipóteses

1. **Erro pré-existente** — O erro `/offline` pode ter existido antes dos nossos commits. Precisamos verificar se o Action anterior passou.
2. **OOM no runner** — O Docker builder tem 6GB de RAM limitado (NODE_OPTIONS='--max-old-space-size=6144'). Com 52 páginas para gerar estaticamente, pode haver OOM.
3. **Componente de layout** — Algum componente global (Navbar, Footer) que foi alterado nos commits de analytics pode estar causando erro em páginas estáticas.

## Plano de Ação

### Tarefa 1: Adicionar `dynamic = 'force-static'` e `export const runtime`

**Arquivo:** `AB0-1-front/app/offline/page.tsx`

A página já tem `export const dynamic = 'force-static'`. Adicionar também `export const revalidate = false` para garantir build estático sem tentar fetch de API:

```typescript
export const dynamic = 'force-static';
export const revalidate = false;
```

### Tarefa 2: Verificar NextResponse no layout ou componentes globais

Verificar se `PostHogProvider.tsx` (alterado em nossos commits) pode estar causando erro durante SSG via importação de módulo não-browser.

A mudança no `PostHogProvider.tsx` adicionou `window.innerWidth` diretamente no `useEffect` — isso é seguro pois `useEffect` só roda no cliente. ✅

### Tarefa 3: Verificar se o erro é de um componente de Navbar ou Footer

O Navbar pode estar fazendo algo que quebra na `/offline`. Verificar se há fetch, cookies() ou headers() sendo chamados sem Suspense no Navbar.
