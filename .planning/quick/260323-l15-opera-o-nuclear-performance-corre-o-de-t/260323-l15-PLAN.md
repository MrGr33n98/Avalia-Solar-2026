## Tarefa 1: Desativar PostHog em Mobile (TBT -1.5s)

**Arquivo:** `AB0-1-front/components/PostHogProvider.tsx`

**Ação:**
Antes de inicializar o PostHog, verificar se o dispositivo é móvel via `window.innerWidth < 768` ou `navigator.connection.saveData`. Se for mobile ou conexão lenta:
- Desativar `session_recording: false`
- Desativar `autocapture: false`  
- Desativar `__preview_remote_config: false`

```typescript
const isMobile = typeof window !== 'undefined' && window.innerWidth < 768;
const isSaveData = typeof navigator !== 'undefined' && (navigator as any).connection?.saveData;
const isSlowConnection = typeof navigator !== 'undefined' && ['slow-2g', '2g'].includes((navigator as any).connection?.effectiveType);

posthog.init(POSTHOG_KEY, {
  // ... existing config
  disable_session_recording: isMobile || isSaveData || isSlowConnection,
  autocapture: isMobile ? false : true,
});
```

**Verificação:** Confirmar que `posthog-recorder.js` e `dead-clicks-autocapture.js` não são carregados em viewport mobile.

## Tarefa 2: Streaming Granular na Home Page (TBT/TTFB)

**Arquivo:** `AB0-1-front/app/page.tsx`

**Ação:**
Remover os `await` síncronos que bloqueiam o início do streaming. A página deve enviar o HTML do Hero imediatamente, sem esperar pela API.

Estratégia:
1. Remover `const [totalCount, categories, featuredCategories, banners] = await Promise.all([...])` do escopo da função `Home`.
2. Passar as **Promises** (não os valores resolvidos) para os wrappers que já usam Suspense.
3. Cada wrapper Async Component faz seu próprio `await` internamente.
4. Garantir que cada seção tenha um `<Suspense fallback={<Skeleton className="..." />}>` com altura fixa para evitar CLS.

**Verificação:** O TTFB deve cair para < 2s — o servidor envia o HTML inicial do Hero antes dos dados da API chegarem.

## Tarefa 5: Reduzir Preconnects no Layout (Quick Win)

**Arquivo:** `AB0-1-front/app/layout.tsx`

**Ação:** Reduzir de 5 para 4 conexões de preconnect. Remover o preconnect para `eu.i.posthog.com` (mantendo apenas `us.i.posthog.com`) — o Lighthouse alerta que mais de 4 preconnects são prejudiciais.

```html
<!-- Remover -->
<link rel="preconnect" href="https://eu.i.posthog.com" crossOrigin="anonymous" />
<link rel="dns-prefetch" href="https://eu.i.posthog.com" />
```

**Verificação:** Warning "More than 4 preconnect connections" deve desaparecer.
